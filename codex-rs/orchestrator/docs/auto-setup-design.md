# 仕様駆動自動セットアップ設計

## 概要

ユーザーがタスクを依頼した際に、configがなければ `.tacodex` フォルダを作成し、
仕様を自動生成してマルチエージェントで実装を進める機能。

## フロー

```
User Request (e.g., "SNSを作って")
         ↓
┌─────────────────────────────────────┐
│ 1. Config検出                        │
│    - tacodex.toml あり → 通常モード  │
│    - なし → 自動セットアップモード    │
└─────────────────────────────────────┘
         ↓
┌─────────────────────────────────────┐
│ 2. .tacodex/ フォルダ作成            │
│    └── SPEC.md (仕様書)             │
│    └── config.toml (オケストレータ設定)│
│    └── prompts/ (エージェントプロンプト)│
│    └── context/ (コンテキスト保存)    │
└─────────────────────────────────────┘
         ↓
┌─────────────────────────────────────┐
│ 3. 親エージェント: 仕様生成          │
│    - ユーザーリクエストを分析        │
│    - 必要なエージェントを定義        │
│    - SPEC.md を生成                 │
└─────────────────────────────────────┘
         ↓
┌─────────────────────────────────────┐
│ 4. オーケストレーター実行            │
│    - SPEC.md を読み込み             │
│    - 依存関係を解決                  │
│    - 子エージェントを並列実行        │
└─────────────────────────────────────┘
         ↓
┌─────────────────────────────────────┐
│ 5. 結果統合・レポート               │
│    - 各エージェントの結果を統合      │
│    - .tacodex/context/ に保存       │
└─────────────────────────────────────┘
```

## `.tacodex/` フォルダ構造

```
.tacodex/
├── config.toml          # オーケストレーター設定
├── SPEC.md              # 生成された仕様書
├── prompts/
│   ├── architect.md     # アーキテクト用プロンプト
│   ├── backend.md       # バックエンド用プロンプト
│   ├── frontend.md      # フロントエンド用プロンプト
│   ├── database.md      # データベース用プロンプト
│   ├── testing.md       # テスト用プロンプト
│   └── review.md        # レビュー用プロンプト
├── context/
│   ├── session.json     # セッション情報
│   ├── decisions.md     # 設計決定の記録
│   └── progress.md      # 進捗記録
└── agents/
    └── {agent_name}/
        └── output.md    # 各エージェントの出力
```

## デフォルト config.toml

```toml
[orchestrator]
enabled = true
max_parallel_agents = 4
agent_timeout_sec = 600
continue_on_failure = false
auto_spawn = true
child_agent_model = "gpt-4o"

[auto_setup]
enabled = true
spec_generation_model = "gpt-4o"
interactive = true  # ユーザーに確認を求めるか
```

## エージェントタイプ

### 1. Architect (設計者)
- プロジェクト構造を設計
- 技術スタックを決定
- ファイル構成を定義

### 2. Backend (バックエンド開発者)
- API実装
- ビジネスロジック
- データベース操作

### 3. Frontend (フロントエンド開発者)
- UI/UX実装
- コンポーネント作成
- スタイリング

### 4. Database (データベース設計者)
- スキーマ設計
- マイグレーション作成
- インデックス最適化

### 5. Testing (テストエンジニア)
- ユニットテスト作成
- 統合テスト
- E2Eテスト

### 6. Review (レビュアー)
- コードレビュー
- セキュリティチェック
- パフォーマンス確認

## 実装計画

1. `auto_setup.rs` - 自動セットアップロジック
2. `spec_generator.rs` - 仕様生成ロジック
3. プロンプトファイル群
4. CLI統合 (`--auto-setup` フラグ)
